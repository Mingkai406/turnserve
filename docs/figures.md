# Figure design and provenance

The README uses four complementary figures: a relational architecture schematic, faceted dispatch maps, measured output curves, and an interruption detail. All are generated by [`scripts/render_figures.py`](../scripts/render_figures.py). No generated illustrations or copied gallery images are used.

## Visual references

The [ggplot2 extension gallery](https://exts.ggplot2.tidyverse.org/gallery/) informed the choice of visual forms:

- [ggraph](https://ggraph.data-imaginist.com/): explicit nodes, edges and ownership groups for the architecture.
- [patchwork](https://patchwork.data-imaginist.com/): aligned facets and asymmetric overview/detail panels.
- [ggforce facet_zoom](https://ggforce.data-imaginist.com/reference/facet_zoom.html): preserve the whole interaction while magnifying the cancellation window.

These are design references, not rendering dependencies. The implementation uses Matplotlib, with a shared palette, editable SVG text, white backgrounds, and restrained axes. DejaVu Sans ships with Matplotlib for portable rendering. Prefill/decode symbols and cancellation markers provide shape cues in addition to color.

## Reproduce

Figure generation requires Python 3.12+ for the pinned plotting dependencies. This is separate from the runtime and trace tools' Python 3.10+ requirement.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r scripts/requirements-figures.txt
.venv/bin/python scripts/render_figures.py
```

SVGs are saved in `docs/assets`. Vector PDFs and 300-dpi PNGs are exported locally to the ignored `runs/figure-exports` directory. Use `--export-dir PATH` to change that destination. Data source hashes and the rendering version are written to [`docs/assets/provenance.json`](assets/provenance.json).

## Meaning of each figure

| Figure | Source | Encoding | Interpretation limit |
|---|---|---|---|
| Architecture | Current C++ runtime and backend | Directed relations and one owner boundary | Schematic; node sizes and arrows are not measured quantities |
| Scheduling map | Three policy JSONL traces | One symbol per `prefill` or `decode` dispatch event; request rows; policy facets | X-axis is dispatch order, not elapsed time or batch identity; square size does not encode chunk length |
| Recorded run | `interleave.jsonl` | Cumulative `token.count`; first token and terminal timestamps relative to submission | Four request lifecycles in one execution; output caps and cancellation differ |
| Cancellation detail | Requests 3 and 4 in `interleave.jsonl` | Full request lifetimes, zoomed enqueue/cancel/accept events, count of `committed` events | Panels A and B use different time scales; acknowledgement timing is not an SLA |

For the numerical figures, the observational unit is a recorded event or request within one functional smoke run. There is one run per policy, not a sample of independent benchmark repetitions. No means, confidence intervals, p-values or statistical rankings are calculated. The input model, decoding setup and uncontrolled hardware conditions are documented in the [run manifest](../results/smoke-cpu/manifest.json).

The SVGs do not add estimated events or interpolate missing measurements. Step curves hold the observed token count until the next event. The old request's partial output remains visible; only its committed-history count is zero.

## Review checks

- All three raw traces pass `scripts/inspect_trace.py` lifecycle checks.
- Each dispatch map has 77 symbols, matching that trace's dispatch event count.
- The interleave trace ends with 48, 7, 3 and 10 emitted tokens for requests 1–4.
- Request 3 has zero commit events; request 4 has one.
- SVG XML, README links and source hashes are checked before publishing.
- Rendered PNG previews are reviewed for label collisions, clipping and consistent semantic labeling.
